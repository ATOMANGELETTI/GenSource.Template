# documents/

Longer-form project documentation that doesn't fit neatly in a README: specs,
architecture decision records (ADRs), design docs.

- **Naming**: descriptive lowercase-hyphenated filenames, e.g.
  `architecture.md`, `adr/0001-config-centralization.md`.
- **Content**: prose documentation intended for humans and agents alike.
  Structured data belongs in [`../data/`](../data/) instead.

No documents exist yet — this is a good place to record *why* this template
is laid out the way it is (e.g. why configs live under `src/configs/`) once
those decisions are written down.
